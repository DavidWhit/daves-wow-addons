## 1. Overview & Default Tabs

Blizzard still owns message rendering, chat filters, the combat log, and `ChatConfigFrame`. Dave's Chat seats Blizzard's dock inside a movable/resizable dialog window with generous inner margins, a collapsible/scrollable left-side chat tab list (auto-fitted up to `1/3` of the window width, or full-width chat when hidden), a bordered inner chat-text frame with an aligned input box below it, a selectable text direction (`Bottom` stock default or `Top` newest-first), an optional faint mode (window chrome fades down to a translucent frosted-glass chat backing until hovered), a top header bar (`Social` at the far left, `Show/Hide Tabs` eye button, `Channels`, optional `TTS`, `Chat Settings` bubble icon, `Window Settings` window icon, and top-right `X` close button), a draggable message-bubble open icon when collapsed, and three default tabs configured once (`layoutVersion = 1`):

| Tab | Frame | Contents |
| --- | --- | --- |
| **Chat** | `ChatFrame1` | Say, emote, party, instance party, whispers (including Battle.net) |
| **Combat Log** | `ChatFrame2` | Blizzard's combat log (`COMBAT_LOG`); filters untouched; `CombatLogQuickButtonFrame_Custom` reparented to `DavesChatAnchor` inside `ns.chatBox` while we hide `ChatFrame2Tab` |
| **General** | `ChatFrame4` | Yell, guild, raid, numbered channels, loot, system, ping, guild achievements, and remaining non-combat groups (`ChatFrame3` is Blizzard's voice transcription window and is left alone) |

SavedVariables (`daves_chatDB`): `enabled` (`true`), `routeChannels` (`true`), `layoutVersion` (`0` until first tab apply), `showTabs` (`true`), `textDirection` (`"bottom"` stock default, or `"top"`), `faint` (`false`), `frostStrength` (`0.5`, `0.0`–`1.0` faint frosted-glass strength on the chat section only), `frostColor` (`nil` for default `{0.82, 0.87, 0.94}`, or `{r, g, b}` from `ColorPickerFrame`), `defaultTab` (`1`, chat frame ID of the Default Window), `width` (`520`, min `300`), `height` (`320`, min `180`), `scale` (`1`, `0.5`–`2.0`), `background` (`0.8`, `0.2`–`1.0`), `backgroundStyle` (`"dark"`), `collapsed` (`false`), `whisperAlert` (`true`), plus `pos` (window anchor) and `iconPos` (draggable message-bubble open icon, initialized to the window's bottom-left corner on first collapse).

## 3. Architecture & Verified Forever UI Facts

- **Single-Pass Layout (`ns:LayoutWindow`)**: `PlaceSettings`, `PlaceHeaderButtons`, `SeatChat`, and `RefreshTabs` are decoupled (none calls the others) and run once in dependency order inside `ns:LayoutWindow()`.
- **Text Direction (`ns.db.textDirection`, `ScrollingMessageFrame.lua:297-301, 591-605, 898-900`)**:
  - `ScrollingMessageFrameSecureMixin:SetInsertMode(insertMode)` is an official untainted elevation barrier exposed for addons, and `SetInsertMode` calls `MarkLayoutDirty()`, so switching re-lays out existing lines live.
  - `"bottom"` (default, matching stock WoW) keeps owned docked frames on `SCROLLING_MESSAGE_FRAME_INSERT_MODE_BOTTOM`. `"top"` switches them to `SCROLLING_MESSAGE_FRAME_INSERT_MODE_TOP` (`1`, fallback `"TOP"`), which anchors `visibleLines[1]` (the newest line at `scrollOffset == 0`) at `TOPLEFT` and grows older messages downward. `ScrollUtil.InitScrollingMessageFrameWithScrollBar` (`ScrollUtil.lua:159-211`) inverts scrollbar percentage and wheel direction automatically on `ChatFrame1..N` when `GetInsertMode() == SCROLLING_MESSAGE_FRAME_INSERT_MODE_TOP`, so no overlay frame is needed above `ChatFrame1..N`.
  - Undocked frames and `"restore"` mode always reset to `SCROLLING_MESSAGE_FRAME_INSERT_MODE_BOTTOM` (`2`, fallback `"BOTTOM"`).
- **Faint Mode & Frosted-Glass Chat Backing (`ns.db.faint`, `ns.db.frostStrength`, `ns.db.frostColor`, `ns.frost`)**:
  - WoW's addon UI API has no real-time screen-space framebuffer blur shader (`SimpleTextureBaseAPI` / `SimpleFrameAPI` cannot sample and blur the 3D scene behind a 2D UI frame). Instead, `ns.frost` (`BACKGROUND` strata on `UIParent`, frame level `fill + 1`, `SetAllPoints(ns.chatBox)` — strictly the inner chat-text pane, never the outer window, header, tab list, or input strip — `SetFlattensRenderLayers(true)`, scaled in lockstep with `ns.anchor` and `ns.fill`) composites a 3-layer neutral-luminance frosted-glass pane tinted via `SetVertexColor` / `SetGradient`: `frost_glass.tga` (`64×64` 9-slice via `SetTextureSliceMargins(16, 16, 16, 16)` with anti-aliased `5px` rounded corners, subsurface edge scatter, and top-left specular bevel rim; `SetColorTexture` fallback if 9-slice margins aren't supported), `frost_grain.tga` (`128×128` `REPEAT` tiled cloudy diffusion + sandblasted micro-grain inset `2px`), and a subtle vertical refraction gradient (`SetGradient("VERTICAL", ...)`). `ns:ApplyFrost()` scales layer alphas from `ns.db.frostStrength` (`0%` clear to `100%` dense frosted glass, default `50%` ≈ `41.5%` effective interior opacity) and tints them with `ns:GetFrostColor()` (`ns.db.frostColor` picked via `d:AddColor` / `ColorPickerFrame`, or default `{0.82, 0.87, 0.94}`) so dark text has contrast against dark 3D scenes while `ChatFontNormal`'s black drop shadow keeps light text crisp on bright scenes.
  - A separate `UIParent` child fader frame (never the anchor, whose `OnUpdate` belongs to `EditMode.Attach` while dragging) lerps `ns.chromeAlpha` toward `0` once the cursor has been off the window for `0.6s` (fade out over `0.4s`) and back to `1` on hover (`0.15s`), while also tracking `ns.frostTextAlpha` from `ns.ActiveChatTextAlpha()` (pure read-only `IsShown()`/`GetAlpha()` scan of `chat.visibleLines` with a single-pass `FontStringContainer:GetRegions()` `"FontString"` fallback, guarding region/shown/alpha/type returns with `issecretvalue` without touching secret message strings or `CircularBuffer`; reset to `nil` when inactive). When no new messages arrive and Blizzard fades the last visible line out (`ScrollingMessageFrameMixin:UpdateFading`), `ns.frostTextAlpha` fades to `0` in lockstep (`ns.frost:Hide()`), and glides right back to `1` (`0.15s`) as soon as a new message arrives or scrolling/tab switches reveal lines. Dragging the `Faint glass` slider (`ns:PreviewFrost()`) or opening `ColorPickerFrame` via `Faint glass color` (`ns:BeginFrostColorPick()`) temporarily fades the outer chrome out (`0.15s`) and forces `textA = 1` so the player always sees a live preview of the frosted-glass chat section over the 3D scene even when chat is quiet. It applies `a` with `DavesChatAnchor:SetAlpha(a)` (border, header, pinned Social / Channels / TTS, close `X`, tab list, `ns.chatBox` border, grips, `CombatLogQuickButtonFrame_Custom`), `ns.fill:SetAlpha(a)` (outer background, tab-column and inner-frame fills), `ns:SyncFrostAlpha()` (`ns.frost:SetAlpha((1 - a) * textA)` when `open and strength > 0 and (ns.db.faint or previewing or a < 0.999)`, hidden at `0`), and `ns:ApplyOwnedChromeAlpha` (`MinimalScrollBar` `0.65 × a`, resting IM edit box `0.35 × a`). Chat frames aren't children of the anchor, so message text stays fully visible. The chrome is kept visible while hovered, resizing (`ns.resizing`), in Edit Mode, while Window Settings is open (except during live frost preview), or while the Say box is focused or holds text. Faded chrome stays clickable, and hovering it brings it back first. Known tradeoff: whisper pulses on tabs and the eye button, plus Quick Join toasts on the pinned Social button, stay invisible until you hover.
- **No Reparenting or Script Hooks on `ChatFrameN` — Synchronous Pre-Draw Seating**:
  - **Why not a separate custom `ScrollingMessageFrame` target?** On Forever (12.x), `ChatFrame1..10` own secure `CircularBuffer` message history (`CircularBuffer.lua:160` `SecureTypes.CreateSecureNumber()`), `SetItemRef(link, text, button, chatFrame)` player report / whisper / mature-language uncensor callbacks (`TransformMessages` / `RemoveMessagesByPredicate` / `UpdateColorByID` keyed on `ChatFrameN:GetID()`), `CombatLogDriverFrame` + `CombatLogQuickButtonFrame_Custom` (`Blizzard_CombatLog.lua:1576, 1696`), and `$parentEditBox`.
  - **Synchronous pre-draw seating & idempotent point/size guards**: `ScrollingMessageFrame` defers line layout to `OnPostUpdate` (`RefreshIfNecessary`). `ns:SeatChat()` uses `ClearAllPointsBase` / `SetPointBase` (`EditModeSystemTemplates.lua:13-17`, avoiding `SetSnappedToFrame` and `OnEditModeSystemAnchorChanged`), **guarded so `ClearAllPointsBase` / `SetPointBase` / `SetSize` only run when points or dimensions actually differ (`> 0.5px`)** — preventing `ScrollingMessageFrameMixin:OnPreSizeChanged` (`MarkLayoutDirty` -> `RefreshLayout` -> `fontStringPool:ReleaseAll()`) and `FCFDock_OnPrimarySizeChanged` (`FCFDock_OnUpdate` -> `FCFDock_UpdateTabs` -> `SeatChat`) from recycling pooled `FontString` lines between `MouseDown` and `MouseUp`! Non-primary docked frames (`ChatFrame2`, `ChatFrame4`, etc.) also receive explicit `SetSize(width, height)` when dimensions change so `self:GetWidth()` in `RefreshLayout()` stays accurate when `ChatFrame1` is hidden by a tab switch. `ns:HookChatPositionGuards()` attaches synchronous `hooksecurefunc` post-hooks to `ChatFrame1` (`ApplySystemAnchor`, `UpdateSystem`, `UpdateSystemSettingWidth`, `UpdateSystemSettingHeight`, `SetPoint`, `SetScale`), `FloatingChatFrame_Update`, `FCF_RestorePositionAndDimensions`, `FCF_DockUpdate`, `FCFDock_ForceReanchoring`, and `EditModeManagerFrame` (`UpdateLayoutInfo`, `ExitEditMode`, `RevertAllChanges`), and `watcher` checks `ns:IsChatSeated()` (pausing only while `ChatFrame1` is actively being dragged or resized in Edit Mode). Every Blizzard reset is undone in the same Lua call stack before `OnPostUpdate` lays out text and before any frame renders.
  - Never `SetParent`, `HookScript`, `SetScript`, or `UnregisterEvent` on `ChatFrameN`, never call `ChatFrame1:Hide()` while `ChatFrame1` is the selected dock tab (hiding non-selected docked tabs in `ns:SyncChatChrome` / `ns:EnforceOwnedChrome` matches `FCFDock_UpdateTabs` and prevents `FloatingChatFrame_Update(1)` from leaving `ChatFrame1` shown on top of `ChatFrame2`/`ChatFrame4`), and always check `rawget(ChatFrame1, method)` before `hooksecurefunc(ChatFrame1, method, ...)`.
- **Margins, Auto-Fitted Collapsible Left Tab List & Direct `editBox` Alignment**:
  - Outer `DialogBorderTranslucentTemplate` (`DialogTemplates.xml`) has an `11px` visible metal rail on all four sides. With `EDGE = 20`, `TOP_EDGE = 12`, `HEADER_GAP = 8`, `COL_GAP = 10`, `BOTTOM_TAB = 19`, and `BOTTOM_BOX = 51`, content sits with balanced `8–9px` visible margin inside the dialog rails on all sides, plus `BOX_INSET_L = 12`, `BOX_INSET_R = 24`, `BOX_INSET_T = 10`, `BOX_INSET_B = 10` inside `ns.chatBox` and `(4, -4)` to `(-5, 4)` inside `ns.tabColumn`.
  - When `ns.db.showTabs ~= false`, `ns:ComputeTabColumnWidth(windowWidth, availHeight)` measures non-secret tab labels via an unconstrained hidden `"GameFontHighlightSmall"` `FontString` (fallback `72px` for secret tab names) and clamps `tabColumn` width to `[76, max(76, floor(windowWidth / 3))]`. Once the window has been hovered while tabs are open (`ns.tabsAutoCloseArmed`), leaving the window (`KeepTabsOpen() == false` — meaning not hovered, not in Edit Mode, not dragging/resizing the window or tab scrollbar thumb, no open `ns.openTabMenu` via `Menu.GetManager():GetOpenMenu()`, no `"NAME_CHAT"` `StaticPopup_Visible`, and Window Settings closed) for `FAINT_DELAY` (`0.6s`) calls `ns:SetShowTabs(false)`. When `ns.db.showTabs == false`, `ns.tabColumn` hides and `ns.chatBox` (plus `ns.frost`, `ChatFrame1..N`, and `editBox`) expands to `boxLeft = EDGE` (full inner width).
- **Hyperlink Clicks & Hover Tooltips (`ChatFrame.OnHyperlinkEnter` / `ChatFrame.OnHyperlinkLeave`)**:
  - `ChatFrame1..N` sit at `LOW` strata (`frameLevel = 5`) with `FontStringContainer` (`propagateHyperlinksToParent="true"`). No `MEDIUM`-strata frame over `ns.chatBox` may enable mouse or mouse wheel (`ns.border`, `ns.chatBox`, and `ns.chatBox.NineSlice` all keep `EnableMouse(false)` and `EnableMouseWheel(false)`), only the active selected docked tab is shown and keeps `SetHyperlinksEnabled(true)` / `EnableMouseWheel(true)` (guarded by `GetHyperlinksEnabled()` / `IsMouseWheelEnabled()` so C++ hyperlink mouse-down state is never reset mid-click), and `frame.clickAnywhereButton` is suppressed while owned so hyperlink clicks (`OnHyperlinkClick` → `SetItemRef` → `ItemRefTooltip` for items/spells/quests, or `HandlePlayerLink` / `HandleBNPlayerLink` for player names: left-click whisper, right-click menu, Shift-click `/who` or insert name) and hovers always reach the active `ChatFrame` on the very first click.
  - Because `ChatFrameMixin:OnHyperlinkEnter` and `OnHyperlinkLeave` (`ChatFrame.lua:27-33`) only broadcast `"ChatFrame.OnHyperlinkEnter"` and `"ChatFrame.OnHyperlinkLeave"` via `EventRegistry`, `Window.lua` registers `EventRegistry` callbacks (100% taint-free, never touching `ChatFrameN` scripts) to show `GameTooltip:SetHyperlink(link)` (or `BattlePetToolTip_ShowLink(text)`) anchored beside `ns.anchor` on hover, and hide it on leave.
  - For player name hyperlinks (`player`, `playerCommunity`, `playerGM`, `BNplayer`, `BNplayerCommunity`), `ShowPlayerHyperlinkTooltip` builds a tooltip on `GameTooltip` displaying the class-colored player name, **level** + race + class, guild (`<Guild> (Rank)`), zone, note, and click hints by combining `C_ChatInfo.GetChatLineSenderGUID` + `GetPlayerInfoByGUID`, visible unit tokens (`player`, `target`, `mouseover`, `focus`, `party1..4`, `raid1..40` when `IsInRaid()`, `nameplate1..40`), `C_FriendList.GetFriendInfo`, `C_BattleNet.GetAccountInfoByID` / `GetGameAccountInfoByGUID`, `C_RecentAllies.GetRecentAllyByGUID`, `C_Club` guild/community rosters (`C_Club.GetGuildClubId`, throttled per `clubID` and cached in `playerInfoCache`), and `/who` results (`WHO_LIST_UPDATE` refreshes an open player tooltip live when Shift-clicking a name runs `/who`).
  - `AnchorOwnedEditBox` anchors `$parentEditBox` (`height = 32`, `ChatFrameEditBox.xml:6`, whose `UI-ChatInputBorder-Left2`/`Right2` art has `5px` horizontal and `4px` vertical transparent padding around a `24px` visible frame) directly to `ns.chatBox` `BOTTOMLEFT (-5, -4)` and `BOTTOMRIGHT (+5, -4)`. That keeps `editBox`'s visible walls pixel-flush with `ns.chatBox` across both tab modes and gives an exact **`8px` visual margin above** (`51 - 43 = 8`) and **`8px` visual margin below** (`19 - 11 = 8`).
- **Taint-Free Unsent-Text Cleanup on Close (`ns:CloseOwnedEditBoxes`) & Tab Context Menu (`OpenTabContextMenu`)**:
  - `C_ChatInfo.SendChatMessage` is `[restricted]` on Forever, and `ChatFrameEditBoxBaseMixin:SendText` (`ChatFrameEditBox.lua:294`) reads `self:GetChatType()` (`self:GetAttribute("chatType")`). Calling `edit:ClearChat()`, `ChatFrameUtil.DeactivateChat(edit)`, `edit:Deactivate()`, or `edit:Hide()` from addon code invokes `self:SetChatType(self:GetStickyType())` → `self:SetAttribute("chatType", ...)`, tainting `"chatType"`!
  - Instead, `DeactivateSingleEditBox` uses **only pure C++ widget methods**: if `edit:HasFocus()` is true while `GetText()` is empty, it temporarily calls `edit:SetText(" ")` before `edit:ClearFocus()` so `OnEditFocusLost` → `ShouldDeactivateChatOnEditFocusLost()` (`self:GetText() == ""`) returns `false` and skips `DeactivateChat`; then it calls `edit:SetText("")`, hides `AutoCompleteBox` if attached, resets `SetFrameStrata("LOW")`, hides `header` / `focusLeft` / `focusMid` / `focusRight` / `$nameLanguage`, and sets `SetAlpha(0)` + `EnableMouse(false)`.
  - Similarly, `OpenTabContextMenu` in `Tabs.lua` uses `MenuUtil.CreateContextMenu` directly instead of calling `FCF_Tab_OnClick(tab, "RightButton")`, avoiding taint on global `CURRENT_CHAT_FRAME_ID`.
- **Click-to-Clear Say Box (`GLOBAL_MOUSE_DOWN`)**: `ChatFrameUtil.ActivateChat` raises the edit box to `DIALOG` strata, and `ShouldDeactivateChatOnEditFocusLost` keeps it there while it holds unsent text, so it can float over the header, tab list, and Window Settings. `ns:GLOBAL_MOUSE_DOWN` (registered only when `C_EventUtils.IsEventValid` allows it, or through `pcall`) checks `ns:OwnedEditBoxActive()` and, when the cursor is over `ns.settingsBar` (which also holds the pinned Social / Channels / TTS buttons), `ns.closeButton`, `ns.dragStrip`, `ns.tabColumn`, a resize grip, or `ns.editDialog`, calls `ns:CloseOwnedEditBoxes(true)`. `keepOpen = true` runs `SyncEditBox(edit, false)` after cleanup so IM style returns to `0.35` alpha and classic style stays hidden. Chat-text clicks are excluded so shift-click link insertion keeps working.
- **Tooltip Anchoring (`ns.AnchorTooltip`)**: Every Dave's Chat tooltip uses `SetOwner(owner, "ANCHOR_NONE")` plus explicit `SetPoint`s beside its owner, which flip toward the screen center, so tooltips never fall back to the default bottom-right anchor. Blizzard's own pinned header buttons (Social / `QuickJoinToastButton`, Channels, TTS) may use `GameTooltip_SetDefaultAnchor` (`SharedTooltipTemplates.lua:87`, `SetOwner(parent, "ANCHOR_NONE")` + default-container corner). A `hooksecurefunc("GameTooltip_SetDefaultAnchor")` post-hook in `ns:HookChatAlerts` checks whether the owner sits inside `ns.settingsBar` (walking up to 4 parents) and re-anchors it with `ns.AnchorTooltip` before any lines are added; every other tooltip in the game is untouched. `EditModeDialog.lua` keeps the kit's own anchors (unmodified).
- **Default Window (`ns.db.defaultTab`)**: Stored as a chat frame ID (`1` = `ChatFrame1`). Temporary whisper tabs can't be the default because Blizzard reuses their IDs. `ns:SelectDefaultTab(final)` runs in all three login passes (immediately, `C_Timer.After(0)`, and `C_Timer.After(1)`) and when the message-bubble icon reopens the window. It selects the frame through the same taint-free `SelectTabFrame` path as a tab click, and only if that frame is `ChatFrame1` or a docked, non-temporary window. Only the final `1s` pass resets a missing default to `1` (earlier passes can run before Blizzard has docked every window). A `hooksecurefunc("FCF_Close")` post-hook (Blizzard's and our `Close Window` both reach it through `FCF_PopInWindow`, `FloatingChatFrame.lua:1844-1858`) resets the default to `1` the moment that window is deleted. The default row shows a `12px` `auctionhouse-icon-favorite` (or `PetJournal-FavoritesIcon`) star, and `ComputeTabColumnWidth` reserves `16px` for it.
- **Social Button (`ns.SocialButton`)**: `Blizzard_QuickJoin` creates `QuickJoinToastButton` on Forever, and `ns.SocialButton()` returns `QuickJoinToastButton`. When it doesn't exist, the header skips the Social slot.
- **Draggable Button Visual Reset (`MakeSnapMover`)**:
  - `RegisterForDrag("LeftButton")` leaves a WoW `Button` in its `"PUSHED"` visual state during/after `OnDragStart` because `OnDragStop` preempts the button's normal `OnMouseUp` release. `MakeSnapMover` calls `SetButtonState("NORMAL", false)` on drag start, during drag `OnUpdate`, and on drag stop, and uses a `50ms` `dragStopTime` guard instead of a sticky boolean so `DavesChatToggle` never stays visually pressed and never swallows the next click.

## 4. Hard Rules ("Do Not Do These")

- Do **not** edit `wowaddons/daves_chat/EditModeDialog.lua` directly; edit `wow-addon-kit/plugins/wow-forever-addons/templates/editmode/EditModeDialog.lua` and sync all Edit Mode addons if the shared dialog ever changes.
- Do **not** register `COMBAT_LOG_EVENT_UNFILTERED` or `COMBAT_LOG_EVENT` (removed on Forever).
- Do **not** call `edit:ClearChat()`, `ChatFrameUtil.DeactivateChat(edit)`, `edit:Deactivate()`, or `edit:Hide()` from addon code (they call `SetAttribute("chatType", ...)` on `ChatFrameEditBox` and taint `C_ChatInfo.SendChatMessage`), and do **not** call `FCF_Tab_OnClick` (taints `CURRENT_CHAT_FRAME_ID`).
- Do **not** build custom settings sliders, checkboxes, or grid-snapping math outside `ns.EditMode.CreateDialog` or `Settings.RegisterVerticalLayoutCategory`.
- Do **not** leave a permanent `OnUpdate` on `DavesChatAnchor` (`ns.EditMode.Attach` owns `anchor`'s `OnUpdate` during drags); keep per-frame watching on the separate `UIParent` watcher frame.
- Always guard potentially secret strings (`ChatFrameNTab:GetText()`, `ChatFrameEditBox:GetText()`, `:GetUnboundedStringWidth()`, `:IsTruncated()`, `CHAT_MSG_CHANNEL_NOTICE` payload) with `not (issecretvalue and issecretvalue(v))` before any comparison or string operation.

## 5. Open Design Questions & Known Tradeoffs

1. **`/daveschat tabs` when "Keep public channels on General" is off**: `ns:ApplyTabLayout()` currently moves numbered channels from `ChatFrame1` to `ChatFrame4` whenever tabs are reset; `routeChannels` only gates subsequent channel joins.
2. **Social buttons while collapsed**: While chat is collapsed to the message-bubble icon, `QuickJoinToastButton` and `ChatFrameChannelButton` stay hidden with `ns.settingsBar` so only the message-bubble open icon remains on screen (`QuickJoinToastMixin:OnHide` pauses Quick Join queue toasts while hidden).
3. **Combat lockdown & Blizzard UI panels**: `ns:OpenChatConfig()` and `ns:OpenOptions()` check `InCombatLockdown()` and print a clean notice in combat rather than calling `ToggleUIPanel(ChatConfigFrame)` / `Settings.OpenToCategory()` while `UIParentPanelManager` blocks non-secure panel opens (`Window Settings` works in and out of combat). Clicking reparented `QuickJoinToastButton` or `ChatFrameChannelButton` during combat may still be refused by `UIParentPanelManager` until combat ends; press `O` (keybinding runs secure) to open Social in combat.
4. **Edit Mode inner `ChatFrame1` box**: `Esc > Edit Mode` shows both `DavesChatAnchor`'s selection box and Blizzard's inner `ChatFrame1` selection box (dragging `ChatFrame1` is undone on exit by the `UpdateLayoutInfo` post-hook).
